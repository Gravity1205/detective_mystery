Algorithm 1: Linear Search by Suspect ID case.c: Lines 201-209 
/* Linear Search scans the array sequentially from index 0 to n-1.
 * Returns array index if targetId matches, otherwise returns -1.
 */
int linearSearchById(const struct Suspect suspects[], int n, int targetId) {
    int i;
    for (i = 0; i < n; i++) {
        if (suspects[i].id == targetId) {
            return i; /* Target found at index i */
        }
    }
    return -1; /* Target not found after complete array scan */
}
College Viva Insight: Linear Search iterates element-by-element with \(O(n)\) time complexity. It requires no sorting precondition, making it ideal for unordered database records.
Algorithm 2: Bubble Sort in Descending Order case.c: Lines 220-234 
/* Bubble Sort compares adjacent suspects and swaps them if the left
 * suspect has FEWER evidence points than the right suspect.
 * This bubbles higher scores to the front (descending order).
 */
void bubbleSortByEvidenceDesc(struct Suspect suspects[], int n) {
    int i, j;
    struct Suspect temp;

    for (i = 0; i < n - 1; i++) {
        for (j = 0; j < n - i - 1; j++) {
            /* Descending check: swap if current is smaller than next */
            if (suspects[j].evidencePoints < suspects[j + 1].evidencePoints) {
                temp = suspects[j];
                suspects[j] = suspects[j + 1];
                suspects[j + 1] = temp;
            }
        }
    }
}
College Viva Insight: By reversing the comparison operator to <, the element with the highest suspicion score bubbles to index 0 on the very first pass.

Why Bubble Sort for \(N=5\)? For small datasets (\(N \le 10\)), the overhead of \(O(n \log n)\) recursive algorithms like QuickSort or MergeSort is unnecessary. Bubble Sort is straightforward to implement, requires zero extra heap memory, and guarantees stability.
